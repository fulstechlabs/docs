Start with one project and a simple report. You can refine it after seeing the results.

## Your first report

<Steps>

1. **Open Reports**  
   In Jira, go to **Apps → Time in Status → Reports**.

2. **Choose your issues**  
   Under **Select issues**, choose **Basic** and a project. Use **JQL** for an advanced filter.

3. **Choose your measurement**  
   Select **Time in status**, **Full history** and **24/7 elapsed time**.

4. **Run the report**  
   Start with **One search page** and **25** issues. Select **Run report**.

</Steps>

## Read the result

![An issue report showing time in each status and a View history button on each row](./assets/report.png)
*Example with demonstration issues.*

| Look at… | To understand… |
| --- | --- |
| Status columns | How long each issue spent in that status |
| Scope and completeness | Which issues were included and whether any data is missing |
| Calculation time | When the current open visits were measured |
| **View history** | The visits behind an issue's result |

A dash means no observed measurement. **Zero** means a measured zero. Do not treat a partial total as complete.

<details>
<summary>Choose the right scope and filters</summary>

**Basic** supports project, issue type and current assignee. Use **JQL** with autocomplete for additional fields or date filters.
**One search page** measures the selected page; **All search pages** collects matching issues within app limits. Use all-pages scope when comparing the complete selected population.
The [calendar guide](../working-calendars/#filter-issues-or-measure-a-period) explains issue filters versus the measurement window.

</details>

## Compare and save

Open **Group results** to compare projects, current assignees, issue types or components.
Choose **Save as new** to keep the report settings; rerun the saved report to get current data.

<details>
<summary>First run slow or cache unavailable?</summary>

The first report may take longer because the app reads Jira history, including issues created before installation.
If **Enable cache for [project]** appears, a Jira administrator can enable the workflow field.
Direct calculation still works without the cache. Follow [Setup and Administration](../administration/) to enable it safely.

</details>

<details>
<summary>What happens to my saved settings?</summary>

**Update saved report** changes a named configuration; **Delete saved report** removes it.
Saved reports keep settings, not frozen results. Last-used inputs are remembered separately in your browser and may disappear when browser storage is cleared.

</details>
