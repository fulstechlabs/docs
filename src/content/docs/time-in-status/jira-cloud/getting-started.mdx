## Your first report

<Steps>

1. **Open Reports**  
   In Jira, go to **Apps → Time in Status → Reports**.

2. **Choose your issues**  
   Under **Select issues**, choose **Basic** and a project. Use **JQL** for an advanced filter.

3. **Choose your measurement**  
   Select **Time in status**, **Full history** and **24/7 elapsed time**.

4. **Run the report**  
   Start with **One search page** and **25** issues. Select **Run report**.

</Steps>

## Read the result

<GuideFigure image={reportImage} alt="Time in Status report showing three demo issue rows, status duration and View history actions" caption="Example result for three issues. Your columns follow your Jira workflow." />

| Look at… | To understand… |
| --- | --- |
| Status columns | How long each issue spent in that status |
| Scope and completeness | Which issues were included and whether any data is missing |
| Calculation time | When current open visits were measured |
| **View history** | The visits behind an issue's result |

A dash means no observed measurement. **Zero** means a measured zero. Do not treat a partial total as complete.

<details>
<summary>Choose the right scope and filters</summary>

**Basic** supports project, issue type and current assignee. Use **JQL** with autocomplete for additional fields or date filters.
**One search page** measures the selected page; **All search pages** collects matching issues within app limits.
The [calendar guide](../working-calendars/#filter-issues-or-measure-a-period) explains issue filters versus the measurement window.

</details>

## Compare and save

Open **Group results** to compare project, current assignee, issue type or component. Add an optional **Second dimension** for a nested comparison, then choose **Total**, **Mean per contributing issue** or **Median per contributing issue**.

For **Time in status**, choose how repeated visits contribute inside each issue and status: total of all visits, first visit, latest visit or average visit. The visit rule is applied before issues are grouped.

Choose **Save as new** to keep a private report configuration. Rerun the saved report to calculate current data. **Update saved report** changes the configuration; **Delete saved report** removes it.

To let teammates reuse the configuration, follow [Sharing and Dashboards](../sharing-and-dashboards/). Shared links contain report settings, not frozen results or export files.

Last-used inputs are remembered separately in your browser and may disappear when browser storage is cleared.
